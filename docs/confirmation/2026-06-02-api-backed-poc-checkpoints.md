# API 기반 PoC 확인 필요사항

이 문서는 Event-to-Operation PoC를 정적/목업 흐름에서 실제 API 기반 흐름으로 확장하면서 사용자가 확인해야 할 사항을 누적 기록한다. 이후 단계에서 새 확인사항이 생기면 날짜와 변경차수를 함께 추가한다.

## 로깅 컨벤션

- 추가 기록은 `[YYYY-MM-DD #NN]` 형식으로 시작한다.
- `#NN`은 해당 날짜의 몇 번째 진행 턴인지 나타내며, 날짜가 바뀌면 `#01`부터 다시 시작한다.
- 한 턴에서 수정한 것, 검증한 것, 사용자가 전후로 확인해야 할 것을 같은 `#NN` 아래에 묶어 기록한다.
- 같은 턴 안에서 구현 전 확인, 구현 결과, 브라우저 검증, 후속 확인사항이 나뉘어도 새 번호를 만들지 않고 같은 턴 항목의 하위 문장으로 기록한다.
- 실제 키, 토큰, 계정 정보처럼 민감한 값은 기록하지 않는다.

## 2026-06-02 진행 전 확인사항

- 이번 단계의 범위는 `web/event_operation_poc.html`과 `poc-server`의 PoC API 흐름이다.
- 실제 외부 채널 발행, 네이버/비즈챗/챗봇 운영계 API 연동, 인증/권한/결제/운영 DB는 이번 단계 범위가 아니다.
- `OPENAI_API_KEY`가 설정되어 있으면 업체 메모리 생성과 채널 초안 생성에서 OpenAI 경로를 시도한다.
- `OPENAI_API_KEY`가 없거나 OpenAI 응답이 스키마 검증에 실패하면 기존 deterministic mock 결과로 fallback한다.
- fallback은 실패가 아니라 데모 지속성을 위한 안전장치이며, 화면과 승인 패키지 trace에 어떤 단계가 `openai`, `mock`, `deterministic`으로 생성됐는지 남긴다.
- 실제 OpenAI 라이브 검증은 사용자가 로컬 `.env`에 유효한 `OPENAI_API_KEY`를 넣은 뒤 확인해야 한다.

## 2026-06-02 진행 후 확인사항

- PoC 상단 상태 문구에서 현재 런타임 모드가 `openai`인지 `mock`인지 확인한다.
- 업체 메모리 생성 후 결과 목록에 메모리 생성 모드가 표시되는지 확인한다.
- 운영 초안 생성 후 승인 패키지의 `생성 모드`와 `API 단계` 표시가 실제 경로와 맞는지 확인한다.
- 승인 패키지 JSON의 `trace.steps`에 `memory`, `taskGraph`, `channelDrafts`, `qualityCheck`가 기록되는지 확인한다.
- OpenAI 키가 없는 환경에서도 전체 PoC 루프가 중단 없이 완료되는지 확인한다.
- OpenAI 키가 있는 환경에서는 초안 문구가 매번 달라질 수 있으므로, 필수 정보/금지어 검수 결과를 함께 확인한다.
