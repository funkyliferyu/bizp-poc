분석·블로그·SEO 적용

분석과 블로그 초안/본문 재생성/SEO provider는 서버에서 compact prompt를 구성하고 inputBudget provenance를 남김.

결론: 현재 로컬 설정에서는 분석/블로그/SEO provider가 실제 OpenAI 호출을 시도합니다. 다만 provider가 없는 경우에는 mock/deterministic fallback으로 돌아가며, UI의 모든 “AI” 또는 “서버 산출” 표기가 매번 LLM 호출을 의미하지는 않습니다.

분석 입력 예산 규칙

  • 분석 prompt는 analysisPromptBudget.ts에서 생성하며, raw provider payload, rendered HTML, image URL 배열, GraphQL snapshot, 중복 body copy는 제외합니다.
  • Blog body는 항목당 최대 1,200자, Place review body는 최대 500자, Place profile은 normalized facts 중심으로 compact합니다.
  • 현재 개발 버전에서는 선택된 Blog 소스가 몇 개든 날짜 기준 최신순 최대 10개만 LLM 분석 prompt에 포함합니다.
  • prompt JSON이 character budget을 넘으면 profile/review evidence를 우선 보존하고 Blog 항목을 날짜 기준 최신순으로 남기며 초과분은 제외합니다.
  • 분석 run 결과에는 selectedItemCount, promptItemCount, omittedItemCount, blogItemLimit, selectedBlogItemCount, promptBlogItemCount, omittedBlogItemCount, promptCharacterCount, promptCharacterBudget, bodyCharacterBudget, promptBudgetReason이 저장됩니다.
  • 그래도 context length 오류가 발생하면 analysis_context_too_large로 sanitize되어 제품용 메시지만 브라우저에 노출됩니다.

블로그/SEO 입력 예산 규칙

  • 블로그/SEO prompt는 blogPromptBudget.ts에서 생성하며, store.metadata, ruleset.ruleset, article JSON, media metadata는 allowlist/compact 구조로 변환합니다.
  • 룰셋은 id/status/version, allowlist summary, compact field list만 보내며 field value는 길이 제한을 둡니다.
  • 본문 재생성/SEO의 article은 title, metaDescription, bounded bodySections/bodyText, seoKeywords, cta, imagePrompts만 포함합니다.
  • media asset metadata는 prompt, alt, placement, generator만 포함하며 CDN 응답/raw provider payload는 제외합니다.
  • content_generations.prompt, contentProvenance, seoScore.provenance에서 provider/model/action/inputBudget을 확인할 수 있습니다.
  • Blog/SEO context-length 오류는 원문 token count를 브라우저에 노출하지 않고 한국어 제품 메시지로 sanitize합니다.

라이브 모드 확인

  • curl -s http://localhost:5177/api/runtime
  • curl -s http://localhost:5177/api/store-learning/provider-readiness
  • 분석 실행 후 GET /api/analysis-runs/:analysisRunId에서 analyzerProvider, analyzerMode, analyzerModel, prompt budget metadata를 확인합니다.
  • 콘텐츠 상세 GET /api/blog-posts/:postId에서 contentProvenance와 seoScore.provenance를 확인합니다.

검증 메모

  • 현재 로컬 runtime: {"mode":"openai","openaiConfigured":true,"model":"gpt-4o-mini"}.
  • provider readiness 기준 Store Learning의 analysis와 blogGeneration은 모두 mode=openai, status=ready.
  • 과거 AI 학습 분석 실패는 OpenAI가 반환한 context length 400 에러였고, 이번 작업으로 분석 prompt budget과 sanitize된 실패 처리를 추가했음.
  • 분석 경로는 현재 예산화됐지만, 블로그 초안/본문 재생성/SEO 재평가 경로는 아직 full payload 리스크가 남아 다음 적용 대상으로 분리함.
  • UI의 “서버 산출 제안”, “다시 생성하기”, “이미지 재생성” 중 일부는 LLM/API 호출이 아닌 local/mock 처리이므로 provider provenance 표시로 구분해야 함.
